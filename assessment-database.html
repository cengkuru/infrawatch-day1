The assessment database · minimum requirements

What the assessment database must record

An assessment database is not just a place to store scores. It is a record that lets someone else reconstruct how every score was decided. Whatever the tool, a spreadsheet, a form system or a purpose-built platform, it must retain the six things below; the structure is free, the retention is not.

The six things to retain, per project and per data point

1Project and classificationThe project's financing form, its classification, and whether it met the PPP definition.
2Stage and evidence stateThe project's lifecycle stage, and for every data point its evidence state: scored, not yet due, not applicable, or searched-and-absent.
3Source and datesFor every find: the source URL, the publisher, the publication date, and the date you accessed it.
4Assessor and reviewerEvery scored point needs a named assessor and, where reviewed, a named reviewer.
5Exceptions and flagsThe reason for every exception: an aged project admitted, a threshold applied, funder-only evidence recorded, or a point flagged for a ruling.
6Sample and case-study statusWhether the project is core sample or drawn from the buffer list (and what it replaced), and which case study it feeds, if any.

The readiness test. If the database can retain a record like this for every applicable point, it is assessment-ready. Self-check: pick any scored point and ask whether a reviewer who was not in the room could see what was scored, from which source, found when, by whom, and why any exception was allowed.
Warning: a tool that only stores scores is not enough. A tool that computes project results beautifully but retains none of the trail fails this standard. Every correction then becomes an argument nobody can settle, every challenge to a score lands on someone's memory, and every handover starts from scratch.

Why this matters

  • Defend: when a government or funder disputes a score, the answer is the recorded URL and access date, not a recollection.
  • Correct: scores change through review or a source reappearing; a correction is safe only when the record shows what the score was based on before.
  • Hand over: assessors change, and the project result must be recomputable by whoever comes next. If the trail lives in one person's browser history, the assessment leaves with them.

These records are the foundation of every other page in this guide.
