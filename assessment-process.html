The assessment · end to end

The assessment scores what a government has made public, one fact at a time

A transparency assessment takes a list of eligible projects and, for each one, checks fact by fact whether the government published it and how easy it is to reach. It never judges whether the project is good; it measures the public record. The output is a scored profile per project and a documented trail behind every score.

The whole method in one sentence. Select eligible projects fairly, then for each of the 40 data points on each project: search the government's channels, record what state the evidence is in, score it 0 to 6, keep the source trail, and average the applicable points into the project result.

The seven steps

1
Establish which projects can enter

Apply the eligibility test: only projects meeting the common financing, timing and implementation rules enter the pool, with qualifying foreign financing as the entry question.

2
Select the country list, and document the selection

Follow the selection and sampling workflow: build the pool, filter it, choose a balanced sample, and record the whole choice before scoring. Never pick a project because its information is easy to find. Pre-commit a buffer list for substitutions.

3
Classify each project

Record its financing form, its classification, and whether it meets the PPP definition. Classification decides which questions apply: every project gets the 40 data points; PPPs additionally get the PPP questions.

4
Search for each fact, properly

For every data point, run a sufficient search of the applicable government channels and record where you looked. An unsearched point is never a zero.

5
Record the evidence state, then score 0 to 6

First settle what state the point is in, using the evidence states: scored, not yet due, not applicable, or searched-and-absent. Then score what was found on the 0 to 6 scale: the turning point is score 3, where official government disclosure begins. Doubts, like conflicting figures, become flags beside the score, never score changes.

6
Keep the trail and review it

Every score enters the assessment database with its source URL, publisher, dates, assessor and reviewer, and the rationale for any exception. A second pair of eyes reviews before anything is reported; hard classification calls are referred to CIPE, never forced to fit.

7
Compute the project result

The project result is the equal-weight average over the applicable points only; excluded points never drag it down. One project yields a profile of scores, a result, and a defensible record of how both were reached.

The two failures that ruin an assessment: selecting projects for their good records (the sample then flatters the system it was meant to test), and scoring zeros without a completed search (the score then measures your effort, not the government's disclosure). Every other mistake can be corrected from the trail; these two poison the data itself.

What comes out the other end

Per country: a documented sample of projects, each with 40 scored data points, flags on the doubtful ones, PPP answers where they apply, and a per-project result. The scores compare; the record explains. Selected projects can then be taken deeper as case studies, which is its own defined process.
