The buffer list · a one-page guide

Selection happens once. Scrutiny never stops.

Fact-checks, reviews and data collection will knock some projects off any list. A buffer list is a short reserve of substitutes that already pass the same test, so one failed project means one documented swap, not a reopened selection.

How a swap works

One core project fails later scrutiny. The swap is small, visible, and recorded. The list keeps its size, and the record shows exactly what changed and why.

Fails eligibilitySwap it, from the buffer, with the record filled in.
Scores poorlyKeep it. The score is the finding.
Data is hard to findKeep it. Discoverability is what the assessment measures, and a profile of zeros is a result, not a defect.

The rules

Six rules keep the buffer a safeguard instead of a back door.

  1. Build it with the list, not after. Buffer projects pass the same eligibility test, to the same standard, on the same evidence discipline as the core list. A weak buffer is no buffer.
  2. Swap only on eligibility, never on results. A project leaves because its financing could not be verified, its status was wrong, or there is no project activity to monitor. It never leaves because it scores badly or its data is hard to find; a project with real activity but no public record is not a failed project, it is the finding.
  3. Keep it short. A handful of genuine substitutes; in practice, country lists of twenty projects have carried three or four. A long buffer is a second selection waiting to happen.
  4. Match like for like where possible. Prefer a substitute from the same financing country first, because the programme's comparison runs on financier origin, then the same sector. Never delay a swap or reopen the wider pool hunting for a perfect match; record the difference and move on.
  5. Document every swap. Which project left, why, which buffer project replaced it, and when; the template below is the minimum. The swap record travels with the methodology. A removed project may re-enter only through a new documented decision, when new evidence resolves the original failure; if a substitute itself later fails, the next buffer project follows the same process.
  6. When the buffer runs out, say so. Do not stretch the criteria to keep the count. Record the gap and raise it to CIPE, which holds the decision between a clearly flagged sub-class and a shorter list. that choice is open with CIPE
