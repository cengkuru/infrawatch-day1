The method · an operating guide

A repeatable publication test for any infrastructure project

Three moves identify the project, test whether its value can be judged from public records, and produce a clear request for the records still needed. Run it on one project; run it on the next the same way.

Nairobi was the start · the method now runs across eleven countries

The test was built in Nairobi on African cases. It has since been run against partner definitions across Africa and Asia. The pattern held everywhere, and it sharpened into one target: public-private partnerships. The forty published fields work well for traditional loans and aid; a PPP hides its real public cost in guarantees, ownership stakes, and long-term payments that those fields do not reach. So the method now leads with the PPP blind spot, and adds a focused set of fields to close it.

Before the test runs: what each country counts

The test can only see a project once a country's own law calls it foreign funded. Those laws run from broad to none at all, and where a country sits decides what its monitoring can even detect. This is the comparison the eleven-country work produced.

Broad
Kenya (to confirm). Catches funding by where it comes from, so it captures the most. The weakness is depth of disclosure, not coverage.
Partial
Ethiopia, Ghana, Nigeria, Malaysia, Nepal. Loans and aid are caught; PPP structures are inconsistently captured, or the rules are split across several separate laws.
Narrow
DRC, Indonesia, Philippines. Anchored on foreign ownership, so funding that arrives as a loan, with no owner, can pass unseen. DRC's Investment Code (Law 004/2002) sets the bar at a 10% stake.
Open
Cambodia (and Sri Lanka, to confirm). No explicit definition of foreign funding, so there is no filter to select or flag a project at all.

Legal references verified against official statutes (July 2026): DRC Law 004/2002; Ghana PFM Act 921; Philippines PPP Code RA 11966; Indonesia Law 25/2007, as amended by Law 6/2023. Kenya and Sri Lanka are still to confirm.

The three moves, step by step

Each move is a question you ask, an input you give, a decision the method makes, and an output you get, with the due-diligence guardrail that keeps it defensible.

Move 1

See it

QuestionWhat is being funded, and by whom?
You enterThe project, the funder, and how it is financed.
The method decidesThe financing type: a government-guaranteed loan, private investment, a long-term contract, a build-and-finance package, or a development loan.
You getThe records this financing type usually needs before its value can be tested.
Due diligenceName the funder from a source; do not infer it.
Move 2

Test it

QuestionCan value for money be judged from public records?
You enterWhether the financing records are public, and whether value can be tested from them.
The method decidesJudgeable up front, only later from outcomes, or not yet, because records are missing.
You getA plain verdict. Records not published at the decision point are themselves the finding.
Due diligenceSay records were not found in reviewed sources, not that they do not exist.
Move 3

Voice it

QuestionWho needs the information, and where might it sit?
You enterWho is affected, and who is likely to hold the missing records.
The method decidesAim the request at whoever holds the records, the funder and the builder, not only the state.
You getA partner action note: a request for the information needed to test value.
Due diligenceRequest information; do not allege wrongdoing.

The due-diligence rules

The method only holds if it is run with restraint. These rules keep every result defensible.

  • Do not claim wrongdoing. The method asks whether the public could judge value, not whether anyone acted in bad faith.
  • Separate your claims. Mark each as an official record, reported by a source, inferred, or not yet verified.
  • Date every source. Records and rulings change; a claim without a date ages badly.
  • Say “not found”, not “does not exist”. A record absent from reviewed sources may still exist elsewhere.
  • Do not call a result external-ready until the sources are checked. Working reads stay internal.
